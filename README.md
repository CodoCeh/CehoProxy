# CehoProxy

**Через туннель ходят только те программы, которые вы выбрали. Всё остальное — напрямую.**

Windows, Linux, macOS. Управление из терминала и из локальной веб-панели.

---

## Знакомая история

Вы включили VPN, чтобы работал ваш ИИ-инструмент. Через десять минут нужно зайти в банк —
он ругается на иностранный адрес. Или Госуслуги, или маркетплейс, или рабочая почта, которая
пускает только из офисной сети. Вы выключаете VPN, делаете дело, включаете обратно — а сессия
в чате оборвалась, генерация слетела, агент в терминале потерял соединение на середине задачи.
И так по кругу весь день.

Причина одна: VPN — штука на весь компьютер. Он не спрашивает, какой программе нужен другой
адрес, а какой — родной. Либо всё, либо ничего.

CehoProxy убирает этот выбор. Вы называете программы, которым нужен туннель, — например
Claude, Codex, Cursor, Gemini. Их трафик идёт через ваш VPN. Всё остальное — браузер, банк,
Госуслуги, рабочие сервисы, игры, обновления системы — идёт как обычно, напрямую. Ничего
не надо включать и выключать: обе стороны работают одновременно.

Отдельно про рабочие компьютеры: там системный прокси нередко просто запрещён правилами.
Здесь он и не нужен — настройки системы не трогаются.

## Что именно происходит

Вы указываете программу. Дальше в туннель попадают все её процессы, включая вспомогательные,
которые она поднимает сама (у программ на Electron их бывает с десяток). Правило строится
по расположению программы на диске, а не по имени файла, — иначе половина процессов ускользнёт.

Если ни одна нода не отвечает, соединения изолированной программы **обрываются**, а не уходят
напрямую. Это сделано намеренно: тихая утечка хуже честного отказа, потому что о ней никто
не узнает.

Подписки в комплект не входят: ссылку выдаёт ваш VPN-сервис, вы вставляете её при настройке.

## Установка

### Одной командой

Linux и macOS — в терминале:

```bash
curl -fsSL https://raw.githubusercontent.com/CodoCeh/CehoProxy/main/scripts/install.sh | sudo sh
```

Windows — в PowerShell, запущенном от имени администратора:

```powershell
irm https://raw.githubusercontent.com/CodoCeh/CehoProxy/main/scripts/install.ps1 | iex
```

Команда скачивает программу для вашей системы, ставит её, заводит короткую команду `chp`
и сразу задаёт пять вопросов: язык, ссылка на подписку, какие программы отправить в туннель,
общий ли это компьютер, запускать ли при старте системы. В конце показывает адрес панели.

### Без командной строки

Если терминал вам не нужен, возьмите со страницы [релизов](../../releases) один архив
для своей системы, распакуйте — и запустите установку из папки:

| Система | Что скачать | Что сделать |
|---|---|---|
| Windows | `CehoProxy-Setup-….exe` | Запустить — обычный установщик с окном |
| Windows | `CehoProxy-…-windows.zip` | Или архивом: распаковать, двойной щелчок по `Установить CehoProxy.cmd` |
| macOS, Apple silicon | `CehoProxy-…-macos-apple.zip` | `Установить CehoProxy.command` — правая кнопка → «Открыть» |
| macOS, Intel | `CehoProxy-…-macos-intel.zip` | то же |
| Linux | `CehoProxy-…-linux-x64.zip` или `-arm64` | `sudo ./install.sh ./cehoproxy` |

В архиве лежит сама программа и установщик рядом с ней — больше ничего скачивать не нужно.
Дальше открывается та же настройка из пяти вопросов.

Правая кнопка на macOS — не прихоть: система не знает нашего разработчика и по двойному
щелчку файл не откроет. Один раз через «Открыть» — и дальше запускается как обычно.

### Что понадобится ещё

Один внешний компонент — движок [sing-box](https://sing-box.sagernet.org). Настройка
предложит скачать его сама; можно поставить и заранее (`brew install sing-box`, пакет
дистрибутива). Почему он не лежит в комплекте — написано в [THIRD-PARTY.md](THIRD-PARTY.md):
у него своя лицензия, и раздавать его вместе с собой было бы неправильно.

## Как этим пользоваться

Наберите `chp` — программа покажет состояние и спросит про то, чего не хватает:

```
  CehoProxy 1.0.0 · Защита включена

  Подписки       мой-впн — работает
  Программы      Claude, Cursor
  Страны         любая (−RU)
  Автозапуск     включён
  Web            http://127.0.0.1:8899
```

Панель открывается по адресу `http://127.0.0.1:8899` — только с этого компьютера, наружу
она не смотрит. Команда `chp open` откроет её в браузере.

Остальное по мере надобности:

```
chp status             состояние и реальный адрес выхода
chp verify             доказать, что программа действительно в туннеле
chp add-app            добавить программу (покажет найденные — выбирайте номером)
chp sub-add            добавить подписку (проверит её сразу)
chp countries          страны выхода, галочками
chp speed 300          выкинуть из пула ноды медленнее 300 мс
chp browser            настройки прокси, если нужно завернуть один браузер
chp help               все команды
```

Всё, что есть в панели, есть и в командах: на сервере без графики это единственный путь.
Язык — русский или английский, спрашивается при настройке.

### Если помощник запускается командой, а не значком

Обычную программу вы запускаете значком, и у неё есть своя папка на диске — по ней
и строится правило. Но часть помощников устроена иначе: они запускаются командой в
терминале и своей папки не имеют. Такая команда — это, по сути, текстовый файл, который
выполняет чужая программа-исполнитель. Одна и та же исполняющая программа обслуживает
десятки разных команд, и компьютер видит именно её, а не вашего помощника. Отправить
в туннель «её» нельзя: туда уедут все команды подряд.

Для таких помощников есть отдельная кнопка. Подставьте имя своей команды вместо `имя`:

```bash
chp wrap имя      # с этого момента команда всегда работает через туннель
chp unwrap имя    # вернуть как было
chp run имя       # разово, ничего не меняя насовсем
```

Дальше вы вызываете команду как обычно — ничего запоминать не нужно. Остальные команды,
даже запускаемые той же самой исполняющей программой, туннель не затронет.

Не знаете, что вписать вместо `имя`? Наберите `chp wrap` без ничего — программа покажет,
что нашла на компьютере, и останется выбрать номер.

## Проверить, что всё работает

Не верьте на слово — спросите:

```bash
chp verify
```

Команда смотрит живые соединения ваших программ и говорит прямо: `ИЗОЛИРОВАНО` или `ТЕЧЁТ`,
с числами. Она не подкладывает пробник и не гадает — берёт локальный адрес каждого соединения
и сверяет с адресом туннеля.

## Что внутри

Написано на **C# для .NET 8**. Поставляется одним самодостаточным файлом: среда выполнения
внутри, ставить .NET отдельно не нужно.

Туннель поднимает sing-box; мы формируем ему конфигурацию и следим за процессом. Свои
интерфейс и таблицы маршрутизации у нас отдельные от его умолчаний — чтобы уборка после сбоя
не задела чужой VPN на той же машине.

Несколько решений, которые стоит знать заранее:

- **Один пул нод из всех подписок.** Ноды всех подписок складываются вместе, живую выбирает
  движок. Переключать подписку целиком не нужно: в одной подписке часть нод рабочая,
  часть мёртвая, и менять надо ноду.
- **Подписка принимается в любом виде:** список ссылок, base64, конфигурация xray или
  sing-box, YAML от Clash, SIP008. Вставляйте то, что вам дали, — разбираться будем мы.
- **Медленные ноды можно отсеять** порогом задержки — `chp speed 300` или поле в панели.
  Замер идёт настоящим соединением; ноды, которые померить нельзя (hysteria2 и tuic работают
  поверх UDP), по скорости не выбрасываются никогда.
- **Самолечение.** Корректного завершения может не случиться в принципе — краш, потеря
  питания. Поэтому следы прошлого запуска снимаются перед каждым стартом, а не после
  остановки.
- **Страна ноды определяется по флагу, названию или коду** — и по-русски тоже. Что не
  распозналось, попадает в группу «страна не определена» и остаётся в пуле: выбрасывать
  рабочую ноду из-за непривычной подписи неправильно.
- **Проверка выхода — настоящим запросом,** а не пингом. Нода отвечает и будучи
  заблокированной, поэтому проверяется то, что нужно именно вам: адрес задаётся в настройках.

## Несколько человек на одной машине

Терминальный сервер обслуживается одной установкой. Туннель один на машину, правило смотрит
на расположение программы — значит действует для всех, кто её запускает. Настраивать каждому
пользователю ничего не нужно.

Отсюда требование к доступу: панель слушает петлевой интерфейс, а он доступен каждому, кто
вошёл на сервер. Поэтому при настройке спрашивается, общий ли это компьютер, и если да —
ставится пароль на панель и на команды.

## Обновления

```bash
chp update
```

Программа смотрит последний релиз, сравнивает версии, скачивает файл для вашей системы
и перезапускает службу. В панели то же самое двумя кнопками.

## Удаление

```bash
sudo chp uninstall --yes
```

Снимает автозапуск, останавливает защиту, убирает правила маршрутизации, короткую команду,
запись в `PATH`, настройки, подписки и скачанный движок. Останется только файл самой
программы; `--purge` уберёт и его.

## Если что-то не так

Сначала спросите саму программу:

```bash
chp doctor
```

Она проверяет права, движок, порт панели, наличие подписки и программ — и на каждую проблему
пишет, что с ней делать. Если это не помогло, откройте
[обсуждение](../../issues) и приложите вывод `chp doctor` и `chp status`.
