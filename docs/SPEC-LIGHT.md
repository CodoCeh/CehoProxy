# CehoProxy Light — спека

Окно программы для Windows, macOS и Linux с тем же набором функций, что у веб-панели, в оформлении Android-клиента.

## Решения владельца (08.11.2026)

- Объём первой версии: всё, что есть в веб-панели.
- Закрытие окна: окно прячется, значок в трее остаётся, VPN работает.
- Платформы: Windows, macOS и Linux в одном выпуске.

## Устройство

- Light — второй экран той же службы CehoProxy. Служба, файл настроек и команды общие с веб-панелью. Отдельной синхронизации нет: оба экрана читают одно состояние.
- Страница Light отдаётся той же службой по адресу `/light` и использует ту же авторизацию (пароль панели, cookie `ceho`).
- Окно — встроенный браузерный движок системы:
  - Windows: WebView2 в существующем трее `ProxyCage.Tray.Windows`;
  - macOS: WKWebView в `ProxyCage.Tray.Mac`;
  - Linux: WebKitGTK (`libwebkit2gtk-4.1`) из `ProxyCage.Tray.Linux`; если библиотеки нет — браузер в режиме приложения (`--app=`), иначе обычный браузер.
- В меню трея: «Открыть CehoProxy Light» (по умолчанию двойной щелчок) и «Открыть веб-панель».

## Служба

Решение при разработке: Light не пишется заново на JavaScript. Это та же серверная панель в другой «шкурке», поэтому все 53 команды и все разделы работают одинаково и синхронизация не нужна.

1. Оформление выбирает cookie `ceho-skin=light`, которую ставит `GET /light` (и перенаправляет на `/`). Окно Light открывает `http://127.0.0.1:порт/light` в своём профиле, поэтому обычный браузер не затрагивается. Запросы с cookie получают оформление Light: тот же HTML, класс `light`, свои стили (`LightUi.cs`), водоворот с анимацией и блок скорости на главной.
2. Номер порта записан в `panel.port` третьим числом (`порт_панели порт_прокси порт_light`), читается `Auth.ReadLightPointer`; значок в трее по нему узнаёт, что Light доступен. Профиль окна Light лежит в папке пользователя (`LocalApplicationData/CehoProxy/light-profile`), а не в `ProgramData`: служебная папка закрыта для обычного пользователя. Повторное нажатие выводит уже открытое окно вперёд.
3. `GET /speed` отдаёт `{"down":байт/с,"up":байт/с}` из Clash API движка; при выключенном туннеле нули. Light опрашивает раз в 2 секунды и рисует график.
4. Пароль и cookie общие. Окно Light и веб-панель читают один `config.json`.

## Экран

- Разделы те же, что в веб-панели, слева колонка навигации (на узком окне — полоса внизу), с переключателем «Простой / Расширенный»: Главная, Программы, Сайты, Подписки, Выход, Проверка, Доступ, Браузер, Журнал, Помощь.
- Главная как на Android: водоворот с иконками программ в туннеле, крупный статус, текущий сервер со страной и задержкой, скорость с графиком, время в сети.
- Анимация водоворота живая; при системном «уменьшить движение» (`prefers-reduced-motion`) — статичная картинка, как в веб-панели.
- Светлая и тёмная тема по системе, шрифты и цвета Android-клиента.
- Ширина окна от 360 px; при широком окне разделы слева, содержимое справа.
- Тексты берутся из `Strings.cs`, языки те же, что в панели.

## Проверка перед выпуском

- Тесты: `/api/state` и JSON-ответы команд; веб-панель не изменилась (существующие тесты зелёные).
- Браузер: каждый раздел Light, ширина 375 и 1280, светлая и тёмная тема, нет ошибок JS; изменение в Light видно в веб-панели и наоборот не позже чем через 2 секунды.
- Окна: Windows 10/11 и Server 2019 (lab), macOS (этот Mac), Debian и Ubuntu (lab) — окно открывается из трея, закрытие прячет его, VPN продолжает работать, повторное открытие показывает актуальное состояние.
- Скилл `cehoproxy-ui-check` дополнить скриншотами Light.

## Не входит

- Отдельные настройки или своё хранилище у Light.
- Управление по сети с другого компьютера (панель по-прежнему слушает только `127.0.0.1`).

## Приём подписок с другого устройства (решение владельца 09.11.2026)

- Протокол тот же, что у экрана «Получить с телефона» в Android, клиент менять не нужно: адрес `http://<ip>:<порт>/p/<секрет из 32 hex>`, служба mDNS `_cehoproxy._tcp` с полями `t` (секрет) и `h` (адрес), телефон шлёт POST с JSON `cehoproxy-share-v1` или форму `link=`.
- Порт открывается только по нажатию «С другого устройства»: слушается один адрес домашней сети (частный IPv4, не туннель и не виртуалка), не `0.0.0.0`; живёт 10 минут; принимает одну отправку до 1 МБ; закрывается после приёма, по «Отмена» и при закрытии окна.
- На Windows на это время добавляется правило брандмауэра `CehoProxy receive` (входящие, TCP, этот порт, только локальная подсеть) и снимается при закрытии приёма.
- Присланное не записывается сразу: окно показывает, что пришло, и ждёт «Добавить».
- Библиотека QR-кода на экране: qrcode-generator (MIT), чтение QR: jsQR (Apache-2.0).
