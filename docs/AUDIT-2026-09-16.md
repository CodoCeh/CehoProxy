# Аудит CehoProxy: проверенные результаты и открытые риски

Это промежуточный аудит, а не подтверждение полной безопасности или завершённой матрицы ОС.

## Подтверждено и исправлено

- Обновление Unix в пути с пробелами теряло executable bit: тест сначала воспроизвёл отказ, File.SetUnixFileMode сохраняет 0755. Старый клиент остаётся в .old.
- Сбой финального перемещения обновления: при отсутствии target и наличии backup исходный клиент возвращается. Тест с отсутствующим скачанным файлом проверяет настоящий путь замены и восстановление original.
- Server: корректный Get-LocalGroupMember по SID Administrators подтвердил, что в группе только Administrator; CehoProbe не является её членом. Выполнение приложений от CehoProbe всё ещё не подтверждено.
- Debian после пяти рестартов остаётся active, свежий warning-журнал пуст.

- Управляющий HTTP: реальный POST /api с Origin чужого сайта выполнялся без пароля. Проверка Origin/Referer/Sec-Fetch-Site добавлена перед маршрутизацией; также закрыт внешний GET /apps/pick. Пять HTTP-регрессий проверяют 403 для чужого источника и 200 для локального CLI и same-origin. Добавлен запрет встраивания панели во frame.
- Чистая Debian: при отсутствии config.json и наличии panel.port ConfigUnreadable ошибочно запрещал запуск daemon даже root. Исправлена ветка отсутствующего файла для повышенного процесса. На VM подтверждены пять рестартов с HTTP 200, Result=success и NRestarts=0; это тест панели без активного туннеля.
- Временный пользователь Debian cehoauditplain (без sudo, только собственная группа) успешно вызвал version и получил панель HTTP 200; бинарник недоступен на запись. Учётная запись удалена после теста.
- Windows: временная задача S4U для CehoProbe не зарегистрировалась (HRESULT 0x80070005). Запуск под ним по-прежнему не подтверждён; наличие административного токена само по себе не объясняет отказ планировщика.

- Unix: `Auth.RestrictConfigAccess` передавал пути в chmod без кавычек. Для каталога с пробелами конфигурация и кеш подписки оставались читаемыми другими пользователями. Регрессионный тест воспроизвёл OtherRead; File.SetUnixFileMode исправил результат на 0600.
- Обновление: Updater принимал файл больше 1 МБ, даже когда его размер не совпадал с размером release asset. Тест с ответом 2 МБ вместо 4 МБ воспроизвёл замену клиента. Теперь обновление отклоняется, .new удаляется, исходный клиент остаётся на месте.
- Windows PowerShell 5.1: локализованный install.ps1 без BOM ошибочно декодировался при запуске через -File. BOM восстановлен. Установщик реально выполнен на Windows Server, скачал клиент с GitHub и установил 1.2.51.

## Исправления прежних выводов

- SSH Administrator на Server VM имеет повышенный токен: IsInRole(Administrator) вернул True. Недостаток UAC-прав не был доказан причиной прежнего Access is denied.
- Invoke-Expression поддерживает param: проверено на VM вызовом, вернувшим 123. Прежнее объяснение удаления param неверно.
- Удаление WaitForExit ранее прошло unit-тесты, но устранение systemd timeout под активным туннелем не подтверждено повторным воспроизведением. Нельзя считать Linux стресс завершённым.
- Создание CehoProbe само по себе не подтверждает успешный запуск приложений под обычным пользователем. Предыдущая net localgroup проверка завершилась синтаксической ошибкой и не доказывает состав групп.

## Приоритеты следующей проверки

1. Управляющие HTTP-маршруты: проверить Origin/CSRF, включая GET /apps/pick; системный процесс не должен принимать команды из произвольного сайта.
2. Windows: проверить ACL бинарников и конфигурации, чтение задачи стандартным пользователем и реальный первый UAC-сеанс.
3. Updater: подпись/хеш артефакта, обрыв передачи, сбой переименования, откат, одновременные обновления и сохранение защиты при ошибке.
4. Завершение: остановка во время старта, проверки выхода и восстановления движка; гонка сторожа с shutdown, лимиты systemd.
5. Прогресс: вложенные операции сейчас могут уменьшать процент; нужны диапазоны этапов и реальный прогресс скачивания, а не только текст этапа.
6. Релизы: сборка из чистой фиксированной ревизии, проверка комплекта assets до публикации latest и установка на каждую поддерживаемую ОС.

## Проверки

Исправлен подтверждённый скачок прогресса doctor: вложенная загрузка подписки ограничена 50–74% перед следующим этапом 75%. Новый DoctorProgressTests проверяет последовательность процентов; полный набор 350/350.

Дополнительная живая проверка: активный Debian-туннель выдержал три последовательных рестарта службы и перезагрузку VM. После восстановления выбранный curl использует прокси, системный — прямой выход. Во время начального запуска выбранное приложение успело выйти напрямую: стартовое окно требует отдельного решения. В журнале наблюдался stream failed: aborted, полностью чистый журнал не заявляется. Windows Server восстановил туннель после перезагрузки через SYSTEM AtStartup без входа пользователя; выбранный и системный curl сохраняют раздельную маршрутизацию. Полный локальный тест после последних исправлений обновления: 349/349. Windows 11 и полноценная матрица обычных пользователей ещё открыты.

Полный локальный dotnet test: 342/342. Два новых теста сначала воспроизвели дефекты и затем прошли. Существуют четыре nullable warnings в AppTunnelTests.

Windows Server: восстановлена установка клиента 1.2.51, но туннель после удаления конфигурации ещё требует настройки. Windows 11 и полный тест разных пользователей остаются незавершёнными. Тесты существующей рабочей сети mini не проводились.
