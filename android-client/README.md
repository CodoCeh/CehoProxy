# CehoProxy for Android

This is a separate Android application module. The desktop application at the repository root remains Apache-2.0; this Android subproject is GPL-3.0-or-later because it links upstream sing-box `libbox`.

The app requires Android 10 (API 29) or newer, matching its configured minimum SDK. It uses Android `VpnService`, supports Always-on VPN through Android system settings, and does not require root. Android allows one active VPN per user/profile. Android TV uses the same screens with D-pad focus and Leanback launcher support.

The app imports sing-box JSON and common share links, fetches subscription URLs, stores routing rules, and exports a backup. Share parsing and config generation cover VLESS, VMess, Trojan, Shadowsocks, Hysteria2, TUIC, NaiveProxy, HTTP, and SOCKS. Naive links include `naive://`, `naive+https://`, `naive+quic://`, and credential-bearing HTTPS forms. The native artifact embeds Cronet and includes `with_naive_outbound`; the API 21 legacy build omits NaiveProxy and is not used by this app. On a physical Samsung Fold, an earlier subscription snapshot passed HTTPS checks for all nine nodes (one NaiveProxy, one Hysteria2, and seven VLESS). The checks used production subscription parsing, outbound configuration, and Android system certificates with an isolated local SOCKS inbound. This establishes native outbound connectivity for that snapshot; per-app Naive VPN routing has not yet been verified.

The refreshed snapshot contains fourteen nodes. In the latest full Android check against the second HTTPS endpoint, NaiveProxy and Hysteria2 succeeded, but only one of twelve VLESS nodes succeeded. Real Android VPN routing through Chrome also failed to load the probe page for selected VLESS nodes 0, 1, and 2 within the observation period; node 4 loaded it successfully. The failure therefore also occurs outside the SOCKS test fixture. Results varied between endpoints and runs, so earlier successful probes do not establish complete reliability.

Diagnostic-only changes did not resolve VLESS nodes 0 and 1: a Firefox TLS fingerprint reached two of the four selected VLESS nodes, while Chrome with local DNS reached one of four. The same selected nodes worked with an independently installed desktop sing-box 1.13.5 bound to the Mac's physical interface, and a direct check confirmed the Mac and phone shared the same public network address. Device time matched the host. These observations narrow the investigation to Android/runtime differences but do not establish a specific engine defect. Production settings and the application APK remain unchanged; diagnostic local DNS is not a production fix.


Build ABI-specific APKs with `./gradlew :app:assembleDebug`; run JVM tests with `./gradlew :app:testDebugUnitTest`. The build omits the multi-ABI universal APK to keep each download limited to one native library. The dependency is pinned to upstream `com.github.singbox-android:libbox:1.14.0` from JitPack. Do not publish this module until the licensing decision is confirmed.
